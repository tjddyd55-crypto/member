# 관리 화면 남은 확인과 체험 재생성 안

비밀 값은 적지 않는다. 계정과 비밀번호는 명령이 환경 변수에서만 읽고, 로그나 이 문서에 출력하지 않는다. Production과 이미 있는 Development 회원 데이터에는 쓰지 않는다.

## 여기서 이미 한 자동 확인

`npm run build -w @member/gathering-admin` 뒤 `npm run e2e -w @member/gathering-admin` 가 로컬 API와 프로덕션 빌드를 Chromium으로 열었다. 너비 1280과 390이다. 결과 표는 `17-admin-coverage.md`다. API는 `NODE_ENV=test`와 `GATHERING_DEV_STORAGE=1`로만 띄운다. 그 조합은 로컬 파일함을 쓰고, R2로 파일을 보내지 않는다.

## 부모가 회원 앱이나 Dev에서 볼 것

로컬이라면 빈 데이터베이스에만 한다. Dev라면 부모가 만든 전용 모임만 쓰고, 끝나면 그 모임 데이터를 운영 데이터와 섞어 두지 않는다.

1. 회원 앱에서 가입한다. 관리 웹에는 가입 화면이 없다.
2. 그 계정으로 모임을 만든다. 목록에 체험 30일이 바로 보여야 한다.
3. 회원 앱 카메라나 앨범으로 사진을 한 장 올린다. 자동 테스트가 연 것은 비회원 업로드 페이지다.
4. 관리 화면에서 모임을 정지한 뒤, 회원 앱에서 그 사진을 연다. 새 업로드와 새 행사는 거절되고 이미 올린 파일은 열려야 한다. 정지를 푼 뒤 만료시켜서 같은 읽기를 한 번 더 한다.
5. 인계를 지명하고, 다음 회장이 수락한 뒤, 회장이 확정한다. 현재 회장만 바뀌고 최초 생성자는 그대로다.
6. 관리 세션을 12시간 두어 자연 만료를 본다. 자동 테스트는 비밀번호 변경으로 세션을 끊는 것까지만 했다.

초기 관리 계정이 없으면 Development API에 환경 변수를 넣은 뒤 `npx tsx scripts/gathering-admin-bootstrap.ts`를 한 번 실행한다. 이미 있으면 다시 만들지 않는다. 아이디와 비밀번호만으로 들어간다. `/enroll`도 로그인 화면이다.

## 모임을 지운 뒤 체험을 또 받는 문제

정하지 않았고 구현하지 않았다. 이름이나 휴대폰이 같다고 새 모임의 체험을 거절하지 않는다. 그렇게 하면 같은 사람의 다른 정당한 모임까지 막힌다.

검토용 안은 삭제 대신 보관이다.

- 모임을 지우면 행을 없애지 않고 보관 시각만 둔다. 체험 청구는 그 모임 ID에 그대로 남는다.
- 보관을 되돌리면 같은 모임과 같은 청구가 돌아온다. 체험을 새로 주지 않는다.
- 새 모임을 만드는 것은 다른 ID이므로 체험을 받는다. 같은 사람이 모임을 여러 개 만드는 정당한 경우를 막지 않는다.
- 보관된 모임을 이름이나 전화번호로 찾아 자동 거절하지 않는다. 반복이 의심되면 슈퍼관리자가 보관 목록을 보고 직접 판단한다.

이 안은 삭제 API가 생기기 전에 제품이 고를 선택지다. 지금 코드는 모임을 지우는 API가 없고, 청구는 모임 ID에만 묶여 있다.
