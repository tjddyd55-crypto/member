# JCI KOREA 통합 앱 — MASTER PLAN

> 장기 개발의 기준 문서. 대화 기억이 아니라 이 디렉터리(`docs/agent/`)를 기준으로 재개한다.
> 개인정보·비밀정보(API 키, 비밀번호, 실제 회원 연락처·주소)는 이 문서들에 절대 기록하지 않는다.

## 1. 최종 목표
기존 **모임 관리 기능(apps/gathering-mobile + apps/api gathering 모듈 + apps/gathering-admin)** 을 유지하면서
JCI KOREA **로컬JC 전자 회원수첩·로컬 운영 기능**을 하나의 iOS·Android 네이티브 앱(JCI KOREA)에 통합한다.

- 최상위 메뉴: 내 로컬 / 내 모임 / 전체 일정 / 내 정보 (Figma 하단 탭: 로컬 · 모임 · 전체 일정 · 내 정보)
- 같은 `User` 계정을 공유하되, 로컬 가입 승인·회원 관계·관리자 권한은 모임과 **독립**
- 로컬 정보는 해당 로컬 **승인(ACTIVE) 회원만** 열람 — 서버(API·DB 조회·파일 다운로드·검색)에서 강제

## 4. 운영 원칙 (요약)
1. 기존 코드 재사용 우선. 기존 DB 구조를 확인하지 않고 중복 테이블을 만들지 않는다 (PHASE0_ANALYSIS §4).
2. 작업 브랜치 → PR → `develop`. CI + 기존 Codex 자동 리뷰. 리뷰 요청 코멘트(`@codex review`) 금지, Bugbot 미사용.
3. `main`/Production 배포, 운영 DB 변경, 유료 외부 API(문자·주소검색 유료 플랜 등)는 사용자 별도 승인.
4. 마이그레이션은 추가형만. 비-QA 데이터 삭제·초기화 금지.
5. ONE FC 프로젝트, 기존 운영 회원수첩 Railway `api`/`Postgres` 서비스는 건드리지 않는다.
6. 실제로 테스트하지 않은 기능은 DONE/PASS로 기록하지 않는다. 실기기 QA 불가 시 BLOCKED.
7. Codex 사용량 소진 시 WAITING_QUOTA + `RESUME.md` 갱신, 무한 재시도·유료 모델 전환 금지.
8. 미확정 정책은 설정 가능한 구조로 만들고, 적용 직전에만 사용자에게 묻는다 (`DECISIONS.md`).

## 5. 핵심 보안 요구 (Phase 공통)
- 모든 로컬 API: 로그인 + 해당 localId ACTIVE 멤버십 검증, 관리자 API는 부여된 권한(직책 아님) 검증
- 사진·PDF·자료 파일: 비공개 버킷 + 권한 검증 후 단기 서명 URL
- 주소·가족·연락처는 로그 기록 금지, 필드별 공개 범위(PrivacySetting) 적용
- 권한 변경·개인정보 수정·YB/OB 전환·인계는 감사로그
- 운영 DB를 개발용 테스트 데이터로 사용하지 않음. 실제 PDF 회원정보를 샘플로 쓰지 않음
